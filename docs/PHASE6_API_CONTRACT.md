# Phase 6 API contract (Period-end and Final Accounts) (extends docs/API_CONTRACT.md and the PHASE2-PHASE5 contracts; same conventions)

Amounts are 2-decimal strings (Indian formatting is for display only), percentages 4-decimal strings, dates `YYYY-MM-DD`, `X-User` on writes, `ServiceError` -> `{code, message, details}`, rule errors `422 {errors:[{rule_id, message, line_no?, ledger_id?, severity?}]}`. `severity` is `error` (blocks) or `warning` (returned with a 200 in `findings` / `warnings`). Every endpoint is under `/clients/{c}`. Every statement endpoint returns `engine_version` and the `rule_status` list (law rows used with their `verification_status`; `pending` is printed on exports).
New error codes (409 unless named): `partner_exists`, `partner_in_use`, `role_conflict`, `adjustment_duplicate` (F-10), `adjustment_state` (voucher no longer draft), `asset_exists`, `asset_in_use`, `event_order` (422, F-21), `run_exists` (F-26), `run_state`, `no_rule` (422, no rate / life row for the date), `closing_stock_missing` (422, F-41), `unclassified` (422, F-44), `statement_blocked` (422, an error finding), `close_blocked` (422, F-60 / F-61 / F-62, details = the list), `year_closed` (409, the FY is frozen), `year_end_voucher` (409, F-64), `already_closed`, `not_closed`, `reopen_blocked` (422, F-64 next FY has postings), `next_year_missing` (422), `export_blocked` (422, F-71).

## Setup and adjustments (package A) - `api/final_adjustments.py`
- `POST /final/setup-ledgers` body `{financial_year_id}` creates (if absent) the system ledgers and sets their roles: `trading_account`, `profit_and_loss` (Reserves & Surplus), `depreciation_expense`, `accumulated_depreciation`, `bad_debts`, `doubtful_debts_expense`, `provision_doubtful_debts`, `stock_ledger`, and for a partnership / LLP `interest_on_capital`, `interest_on_drawings`, `partner_remuneration`; a company's `surplus_in_pl` is its existing Surplus ledger. -> `{roles:[{role, ledger_id, ledger_name, created}]}` (idempotent; audit-logged).
- `GET /final/ledger-roles` -> `[{role, ledger_id, ledger_name}]`; `PUT /final/ledger-roles/{role}` body `{ledger_id}` -> `{"ok":true}` | `409 role_conflict` (ledger already has another role) | `422 F-02` (wrong group).
- `GET /partners` -> `[{id, name, capital_ledger_id, current_ledger_id, is_active}]`; `POST /partners` body `{name, capital_ledger_id, current_ledger_id?}` -> `201 {id}` | `409 partner_exists`; `PUT /partners/{id}`; no delete (`is_active`).
- `GET /partners/terms?financial_year_id=` -> `{rows:[{partner_id, name, profit_share_percent, interest_on_capital_rate, interest_on_drawings_rate, remuneration_annual, deed_reference}], share_total, share_ok}`; `PUT /partners/terms/{financial_year_id}` body `{rows:[...]}` replaces the FY's terms -> `{"ok":true}` | `422 F-62` (shares not 100.0000) | `422` (deed reference missing) | `409 year_closed`. Audit-logged with old and new rows.
- `POST /adjustments/preview` body `Adjustment` -> `{amount, lines:[{ledger_id, ledger_name, debit, credit}], narration, params, findings}` (no write). `Adjustment = {adj_type, as_on_date, basis_note, amount?, debit_ledger_id?, credit_ledger_id?, party_ledger_id?, rate_percent?, partner_id?, months?, auto_reverse_on?, duplicate_reason?}`. `amount` is required for outstanding / prepaid / accrued / in-advance / provision / bad debt and **rejected** (`422 F-05 / F-07 / F-08`) for provision for doubtful debts, interest and remuneration, which the engine computes.
- `POST /adjustments` same body -> `201 {adjustment_id, voucher_id, auto_reverse_voucher_id|null, amount, lines}`: creates the DRAFT journal through the voucher service (it is approved and posted like any voucher) and the `adjustment_entries` row, one transaction | `422 F-01..F-10` | `409 adjustment_duplicate`.
- `GET /adjustments?financial_year_id=&adj_type=` -> `[{id, adj_type, as_on_date, amount, basis_note, params, voucher_id, voucher_status, voucher_number|null, auto_reverse_voucher_id|null}]`.
- `DELETE /adjustments/{id}` -> `{"ok":true}` only while the voucher is a draft (deletes the entry and the draft journal) | `409 adjustment_state`. A posted adjustment is undone by the ordinary voucher reversal.

## Fixed assets and depreciation (package B) - `api/final_assets.py`
- `GET /fixed-assets?q=&active=` -> `[{id, asset_no, name, asset_ledger_id, accumulated_dep_ledger_id, is_depreciable, it_block_key, sched2_class_key, useful_life_years, residual_value, book_method, is_active, cost, additions, disposed}]`; `POST /fixed-assets` body `{asset_no, name, asset_ledger_id, accumulated_dep_ledger_id?, is_depreciable, it_block_key?, sched2_class_key?, useful_life_years?, life_override_reason?, residual_value, book_method?}` -> `201 {id}` | `409 asset_exists` | `422 F-20 / F-24` (the class life is copied when `useful_life_years` is omitted; a different life needs `life_override_reason`); `PUT /fixed-assets/{id}` (setup fields only while no depreciation run exists for a closed or posted year: `409 asset_in_use`).
- `GET /fixed-assets/rules?as_on=` -> `{it_blocks:[{block_key, description, rate, act, verification_status, source_reference}], sched2_classes:[{class_key, description, useful_life_years, max_residual_percent, verification_status}], half_rate_days, half_rate_percent}` (the rule rows in force on the date).
- `GET /fixed-assets/{id}/events`; `POST /fixed-assets/{id}/events` body `{kind: opening|purchase|addition|disposal, event_date, put_to_use_date?, amount, accumulated_dep_bf?, voucher_id?, note?}` -> `201 {id}` | `422 event_order` (F-21) | `409 year_closed`; `DELETE .../events/{event_id}` | `409 year_closed`. Audit-logged.
- `GET /fixed-assets/register?financial_year_id=` -> `{rows:[{asset_id, asset_no, name, ledger, opening_cost, additions, disposals, closing_cost, opening_accumulated, depreciation_for_year, disposal_accumulated, closing_accumulated, net_block, put_to_use_dates}], totals}` (book view from the latest saved run and the events; the Phase 6 Fixed Assets note uses it).
- `POST /depreciation/book/preview` body `{financial_year_id}` -> `{lines:[{asset_id, asset_no, method, cost, opening_accumulated, wdv_rate_percent, days_used, days_in_year, depreciation, closing_accumulated, rule_status}], total, journal_lines, disposal_workings:[{asset_id, proceeds, book_value, profit_or_loss}], findings}` (no write; F-23..F-25).
- `POST /depreciation/book/run` body `{financial_year_id}` -> `201 {run_id, voucher_id, total}` creates the draft Journal (F-26) | `409 run_exists` | `422 no_rule`; `GET /depreciation/book/runs?financial_year_id=` -> `[{run_id, voucher_id, voucher_status, total, created_at}]`; `DELETE /depreciation/book/runs/{run_id}` only while the voucher is a draft (`409 run_state`); a posted run is undone by reversing its voucher.
- `PUT /depreciation/it/openings/{financial_year_id}` body `{rows:[{block_key, opening_wdv}]}` (first year; `source = entered`) -> `{"ok":true}` | `409 year_closed`.
- `GET /depreciation/it/working?financial_year_id=` -> `{blocks:[{block_key, description, rate, rate_act, rate_verification, opening_wdv, additions_full, additions_half, disposals, depreciation, closing_wdv, flags:[...], assets:[{asset_id, asset_no, cost, put_to_use_date, days, half}]}], total_depreciation, status: draft|final, findings}` (recomputed; a WORKING only, F-30..F-34); `POST /depreciation/it/working/finalize` body `{financial_year_id}` -> `{"ok":true}` (stores the final working; used by the close for the carry-forward) | `422` (a block with a flag needs `acknowledged_flags: [block_key...]` in the body).
- `GET .../export` of the register, the book run and the IT working -> `.xlsx` (package E format).

## Closing stock, Trading / P&L / Balance Sheet (package C) - `api/final_statements.py`
- `GET /final/closing-stock?financial_year_id=` -> `{approved:{as_on_date, source, inventory_method, cost_value, write_down, carrying_value, basis_note, approved_by, approved_at, detail}|null, proposal:{...Phase 5 closing-stock report totals and rows...}|null}`; `PUT /final/closing-stock/{financial_year_id}` body `{source: inventory_report|manual|none, as_on_date, cost_value?, write_down?, basis_note}` (for `inventory_report` the values are read from the Phase 5 report by the service, never typed; `manual` needs `cost_value`, `write_down`, `basis_note`; `none` = zero stock, service clients only) -> `{"ok":true, carrying_value}` | `422 closing_stock_missing / F-41` | `409 year_closed`. Audit-logged with old and new.
- `GET /final/trading?financial_year_id=&as_on=` -> `Statement` (below); `GET /final/profit-loss?...&format=vertical|horizontal`; `GET /final/balance-sheet?...&format=vertical|horizontal`. `as_on` defaults to the FY end; an earlier date gives a provisional statement (closing stock must still be approved for that date, else the statement carries the F-41 error). For a **company** client these three return `422 use Schedule III endpoints` pointing at `/final/sch3/*`.
- `GET /final/appropriation?financial_year_id=` (partnership / LLP) -> `Statement` with the net profit before appropriation, interest on capital, interest on drawings, remuneration and each partner's share (F-43, F-62).
- `GET /final/ledger-positions?financial_year_id=&as_on=` -> `[{ledger_id, name, group_code, opening, debit_total, credit_total, closing}]` (the statements' input and the drill-down target; excludes the closing vouchers of a closed year).
- **Statement** = `{key, format, title, from_date, to_date, left:[Line], right:[Line], totals:{gross_profit?, net_profit?, total_assets?, ...}, notes:[{note_no, title, lines:[Line]}], findings:[{rule_id, message, severity, ledger_id?}], engine_version, rule_status:[...], basis:{closing_stock_method, closing_stock_source, entity_type}}`; `Line = {code, label, amount, previous_amount|null, note_no|null, level, is_total, drill:[{ledger_id, ledger_name, amount}]}`. Horizontal uses `left` (debit / liabilities) and `right` (credit / assets); vertical and Schedule III use `left` only. Drill-down opens `/ledgers/{ledger_id}/statement?from=&to=` (Phase 1).

## Schedule III (package D) - `api/final_sch3.py`
- `GET /final/sch3/classification?financial_year_id=` -> `{lines:[{format_key, line_code, label, section}], ledgers:[{ledger_id, name, group_code, line_code|null, source: ledger|group_firm|group_default|none, cf_class|null}], unclassified:[ledger_id], defaults:[ledger_id]}`; `PUT /final/sch3/classification` body `{rows:[{ledger_id, line_code?, cf_class?, note?}]}` (upserts `client_ledger_fs_map`) -> `{"ok":true}` | `422` (unknown line / a P&L line on a balance-sheet ledger). Audit-logged.
- `GET /final/sch3/balance-sheet?financial_year_id=&as_on=`, `GET /final/sch3/profit-loss?financial_year_id=` -> `Statement` (format `sch3`) with notes and previous-year comparatives (`previous_amount`, `previous_source: snapshot|recomputed|none`), findings F-44 / F-44b / F-45 / F-46; `GET /final/sch3/notes?financial_year_id=` -> the numbered notes only. `422 unclassified` when F-44 errors exist (the response still lists them).
- Built shape (package D): classification `ledgers[]` also carry `nature` and `has_activity`; `lines[]` carry `cf_class` and `verification_status`; the response has `rule_status`. A `rows[]` entry with neither `line_code` nor `cf_class` removes the override. A Balance Sheet ledger may go to any Balance Sheet line (contra ledgers net, negative drill amount) but never to a Profit and Loss line (`422 invalid_line`). Statements add `rule_status_summary`, `basis`, `previous_source`; `422 unclassified` carries `details = {unclassified, findings, statement}`; F-40 / F-41 / F-44b errors come back in `findings` with 200. `GET /final/sch3/notes` -> `{notes, findings, engine_version, rule_status, rule_status_summary, basis}`. Non-company: `409 not_company`.
- Only for `entity_type = company`; other entities get `409` pointing to the non-company endpoints.

## Cash flow and export (package E) - `api/final_cashflow.py`, `api/final_export.py`
- `GET /final/cash-flow?financial_year_id=` -> `Statement` (key `cash_flow`): sections A operating, B investing, C financing, net increase, opening and closing cash, the reconciliation to the balance sheet (F-49, F-50); lines carry drill-down to the ledgers behind each movement. Available for any entity (required for companies); `422 statement_blocked` when the cash reconciliation fails.
- `GET /final/export?financial_year_id=&format=xlsx|pdf&statements=trading,profit_loss,balance_sheet,cash_flow,appropriation&layout=vertical|horizontal` -> the file (`Content-Disposition` with client and FY in the name). Company clients export the Schedule III statements and notes; every sheet / page has the header (client, FY, basis, engine version, `pending` law statuses) and each line's drill-down ledgers (a `Ledgers` sheet with the ledger statements' totals, hyperlinked from the lines in Excel; printed as "(ledger: amount)" in PDF). `422 export_blocked` while a statement has an error finding (F-71).

## Year-end close (package F) - `api/final_close.py`
- `GET /final/close/check?financial_year_id=` -> `{ready: bool, items:[{rule_id, ok, message, details?}], net_profit, appropriation_preview:[{ledger_id, name, amount}], vouchers_preview:[{step, voucher_date, reference_no, lines}], carry_preview:{ledger_count, total_debit, total_credit, bills_count, stock_items, it_blocks}, next_financial_year:{id|null, exists}}` (no write; F-60..F-62, F-65).
- `POST /final/close` body `{financial_year_id, create_next_year: bool}` -> `201 {close_id, voucher_ids:{trading, profit_loss, appropriation}, net_profit, carried}`: in ONE transaction creates, approves and posts the three Journals through the voucher service, locks the FY's periods, stores the final snapshots, finalises the IT workings, carries forward openings / bills / stock / IT blocks | `422 close_blocked` (F-60/61/62/65/66, with the list) | `422 next_year_missing` (unless `create_next_year`) | `409 already_closed`. Audit-logged (close, each voucher, each carried block).
- `GET /final/close?financial_year_id=` -> `{status: open|closed|reopened, close_id|null, closed_by, closed_at, net_profit, voucher_ids, carried, reopened_by, reopened_at, reopen_reason}`.
- `POST /final/close/{close_id}/reopen` body `{reason}` -> `{"ok":true, reversal_voucher_ids}`: unlocks the periods, reverses the three closing vouchers (appropriation first, trading last) dated the FY end through the voucher service, supersedes the snapshots and final workings, removes the carried openings of the next FY (only while it has no posted voucher), marks the close `reopened` | `422 reopen_blocked` (F-64) | `409 not_closed`.
- Direct `POST /vouchers/{id}/reverse` of a closing voucher -> `409 year_end_voucher` (F-64, hook `guard_reverse`).
- Posting, editing or reversing anything dated in a closed year is refused by the existing period lock (V-07); closing stock, partner terms, adjustments, depreciation runs, IT openings, opening balances / bills / stock opening and asset events of a closed year are refused by the database (`409 year_closed`).
