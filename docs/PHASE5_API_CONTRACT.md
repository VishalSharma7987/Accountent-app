# Phase 5 API contract (Inventory, trading) (extends docs/API_CONTRACT.md, PHASE2-PHASE4 contracts; same conventions)

Amounts are 2-decimal strings, **quantities strings with at most 3 decimals** (4th decimal -> `422 S-02`), unit costs 4-decimal strings (display only), dates `YYYY-MM-DD`, `X-User` on writes, `ServiceError` -> `{code, message, details}`, rule errors `422 {errors:[{rule_id, message, line_no?, item_id?, severity?}]}`. `severity` is `error` (blocks) or `warning` (returned with a 200 / in the `warnings` list).
New error codes (409 unless named): `godown_exists`, `godown_in_use`, `sku_exists`, `stock_item_exists`, `stock_item_in_use`, `policy_exists`, `policy_locked` (method change after movements, S-04), `opening_exists`, `period_locked` (422, S-09 / S-20), `negative_stock` (422, S-01 in `block` mode), `journal_state` (invalid status change), `journal_reversal_blocked` (422, S-11 / S-17), `no_policy` (422, S-04), `no_original_movement` (422, S-12).
Money is never typed for outward movements: no endpoint accepts a cost for a sale, return, write-off or transfer (S-13).

## Masters (package A) - `api/inventory_masters.py`
- `GET /clients/{c}/godowns` -> `[{id, name, is_active}]`; `POST` body `{name}` -> `201 {id}` | `409 godown_exists`; `PUT /clients/{c}/godowns/{id}` body `{name?, is_active?}` (deactivate only when it holds no stock: `409 godown_in_use`).
- `GET /clients/{c}/stock-items?q=&active=&financial_year_id=` -> `[StockItem]`; `StockItem = {item_id, sku, name, hsn_sac, uqc, default_godown_id, default_godown_name, is_active, has_entries}` (name / hsn / uqc come from the GST item). With `financial_year_id` the row also has `opening_qty, opening_value` (sum over godowns).
- `PUT /clients/{c}/stock-items/{item_id}` body `{sku, default_godown_id, is_active?}` (the item must be an existing goods GST item of the client: create it with `/gst/items` first; create or replace) -> `{"ok":true}` | `409 sku_exists` | `422 S-03` (service item / inactive) | `422 S-07` | `409 stock_item_in_use` (deactivation with closing stock <> 0, S-18). No delete.
- `GET /clients/{c}/inventory/policy?financial_year_id=` -> `{financial_year_id, valuation_method: "fifo"|"wa_periodic"|"wa_moving", negative_stock_mode: "block"|"warn", set_by, set_at}` | `422 no_policy`; `PUT` body `{valuation_method, negative_stock_mode}` -> `{"ok":true}` | `409 policy_locked` (the FY has movements and the method differs) | `422 period_locked`. `POST /clients/{c}/inventory/policy/copy` body `{from_financial_year_id, to_financial_year_id}` -> `{"ok":true}` | `409 policy_exists`.
- `GET /clients/{c}/inventory/opening?financial_year_id=` -> `{rows:[{item_id, sku, name, godown_id, godown_name, quantity, value, unit_cost}], total_value, ledger_opening_value|null, difference|null}` (S-08: the Stock-in-hand ledger opening balance and the difference, information only). `PUT /clients/{c}/inventory/opening/{financial_year_id}` body `{rows:[{item_id, godown_id, quantity, value}]}` replaces the whole opening of the FY -> `{"ok":true, "total_value"}` | `422 S-02 / S-03 / S-07 / S-08` | `422 period_locked`. Audit-logged with old and new rows.

## Voucher integration (package C) - `api/vouchers.py` (existing endpoints)
`POST/PUT /clients/{c}/vouchers` (invoice mode, Phase 3 `gst.items[]`) accept an optional `stock` object on an item line; the line's `item_id` decides whether stock is affected:
```
gst.items[i].stock = { godown_id|null,            // null = the item's default godown
                       original_movement_id|null  // Credit / Debit Note only: the sale / purchase movement the goods came back from / went back to
                     }
```
- Sales / Purchase: a stock item's line always moves stock; `stock` only chooses another godown. Credit Note / Debit Note: stock moves **only** when `stock` is present (value-only notes omit it); then `original_movement_id` is required (`422 S-12`).
- Response item line gains `stock: {godown_id, godown_name, kind, quantity, original_movement_id}` (kind as it will be / was posted; after posting also `movement_id`) or `null`.
- `POST /clients/{c}/vouchers/stock-preview` same body as create -> `{movements:[{item_id, godown_id, kind, quantity, cost|null}], errors:[...], warnings:[...]}` (no write; S-01 chronology result incl. stock after this voucher per item / godown; `cost` is the engine's computed outward cost, null when only known at period end).
- Rules fire at save (S-02, S-03, S-06, S-07, S-12), approve and post (S-01 again over the whole chronology; `422 negative_stock` in `block` mode, a warning in `warn` mode). Posting appends the movements in the same transaction (S-05). A reversal appends mirror movements (S-17) or fails with `422 journal_reversal_blocked`-style `S-17` error and nothing is reversed.
- `GET /clients/{c}/stock-items/{item_id}/returnable?on=` -> `[{movement_id, kind, voucher_number, date, quantity, already_returned, returnable}]` (candidates for `original_movement_id`).

## Stock journals (package D) - `api/inventory_journals.py`
`Journal = {id, journal_type: "transfer"|"write_off", journal_number|null, journal_date, narration, reason_code|null, reason_note|null, status, financial_year_id, lines:[{line_no, item_id, item_name, from_godown_id, to_godown_id|null, quantity}], created_by, approved_by, posted_by, reversed_by, reverse_reason}`; `reason_code` in `damage|expiry|theft|loss|sample|other`.
- `POST /clients/{c}/stock-journals` body `{journal_type, journal_date, narration, reason_code?, reason_note?, lines:[...]}` -> `201 Journal` (draft) | `422 S-02 / S-03 / S-07 / S-10`; `PUT .../{id}` (draft only: `409 journal_state`); `DELETE .../{id}` (draft only); `GET .../{id}`; `GET /clients/{c}/stock-journals?financial_year_id=&journal_type=&status=&from=&to=`.
- `POST .../{id}/approve` -> Journal; `POST .../{id}/post` (S-01 over the chronology; number `SJ/2026-27/0001` assigned; movements appended: `transfer_out` + `transfer_in` per transfer line, `write_off` per write-off line) -> Journal | `422 negative_stock`; `POST .../{id}/reverse` body `{reason}` -> Journal (status `reversed`, mirror movements appended) | `422 journal_reversal_blocked`.
- Rows are audit-logged for create, update, approve, post, reverse.

## Reports and NRV (package E) - `api/inventory_reports.py`
- `PUT /clients/{c}/inventory/nrv/{financial_year_id}` body `{as_on_date, rows:[{item_id, nrv_per_unit, basis_note}]}` (upsert per item and date; a row with `nrv_per_unit` null deletes it) -> `{"ok":true}` | `422 S-15` (negative, > 2 decimals, blank basis) | `422 period_locked`; `GET .../nrv/{financial_year_id}?as_on=` -> `{rows:[{item_id, name, as_on_date, nrv_per_unit, basis_note, entered_by, entered_at}]}`. Audit-logged.
- `GET /clients/{c}/inventory/stock-register?financial_year_id=&from=&to=&item_id=&godown_id=` -> `{policy, from, to, rows:[{item_id, sku, name, uqc, opening_qty, opening_value, inward_qty, inward_value, outward_qty, outward_value, closing_qty, closing_value, by_godown:[{godown_id, closing_qty}]}], totals:{opening_value, inward_value, outward_value, closing_value}, errors, warnings, engine_version}`. `from` defaults to the FY start, `to` to the FY end. Window rules for `wa_periodic`: see PHASE5_PLAN.md. With `godown_id` the quantities are that godown's and the value columns are `null` (valuation is per item).
- `GET /clients/{c}/stock-items/{item_id}/ledger?financial_year_id=&from=&to=` -> item movement list: `{rows:[{date, seq, kind, voucher_number|journal_number, godown_id, in_qty, in_value, out_qty, out_value, balance_qty, balance_value}]}` (outward and return values are the engine's computed cost; drill-down to the voucher).
- `GET /clients/{c}/inventory/closing-stock?financial_year_id=&as_on=` -> `{policy, as_on, rows:[{item_id, sku, name, closing_qty, cost_value, nrv_per_unit|null, nrv_value|null, write_down, carrying_value}], totals:{cost_value, write_down, carrying_value}, items_without_nrv:[item_id], errors, warnings}` (S-15, S-16; the lower-of-cost-and-NRV report). `as_on` defaults to the FY end.
- `GET .../stock-register/export` and `.../closing-stock/export` -> `.xlsx` (same data, formatted, with the method and as-on date in the header).
- Every report recomputes from posted movements (nothing stored); a negative balance found in `warn` mode appears in `warnings` with its date (S-16).
