# Phase 3 API contract (extends docs/API_CONTRACT.md and PHASE2_API_CONTRACT.md; same conventions: amounts are 2-decimal strings, rates are strings with up to 4 decimals, quantities strings with up to 3 decimals, dates YYYY-MM-DD, periods `YYYY-MM` (month) or `YYYY-Qn` with the financial-year-style quarter start given as `period_start`, `X-User` on writes, ServiceError -> `{code, message, details}`, rule failures -> `422 {"errors":[{rule_id, message, line_no}]}` where `line_no` is the voucher line, and for invoice item problems `details.item_line_no` is set)

New error codes (409 unless named): `registration_exists`, `registration_in_use`, `item_exists`, `ledger_role_missing` (422, `details.roles`), `no_rate_rule` (422), `import_duplicate`, `import_invalid` (422, `details` = `[{row, message}]`, row 0 = whole file), `itc_invalid_transition`, `reversal_exists`, `nothing_to_reverse`, `working_final`, `period_invalid` (422), `not_gst_client` (422), `link_invalid`, `link_exists`.
Every response that uses rule data also carries `rule_status: {"worst": "pending"|"secondary_verified"|"verified", "tables": {"rate": "...", ...}, "pending_sources": ["..."]}` (G-55) so the screens can show the badge.

## GST masters (package A)
`Registration = {id, gstin, state_code, state_name, registration_type: "regular"|"composition", return_frequency: "monthly"|"qrmp", composition_category: "manufacturer"|"trader"|"restaurant"|"service_provider"|null, trade_name, effective_from, effective_to|null, is_active, ledger_roles: {role: {ledger_id, ledger_name}}}`
- `GET /clients/{c}/gst/registrations` -> `[Registration]`; `GET /clients/{c}/gst/registrations/{id}`
- `POST /clients/{c}/gst/registrations` body `{gstin, registration_type, return_frequency?, composition_category?, trade_name?, effective_from, effective_to?}` -> `201 {id}` | `422 errors G-01..G-06` (G-06 includes an overlapping period of the same GSTIN) | `409 registration_exists` (same GSTIN and start date). The state code is taken from the GSTIN (never typed). GSTIN trimmed and upper-cased.
- `PUT /clients/{c}/gst/registrations/{id}` (same body without gstin; `effective_to` closes a registration; `is_active`) -> `{"ok":true}` | `422 errors` | `409 registration_exists|registration_in_use` (invoices already issued outside the new period)
- `PUT /clients/{c}/gst/registrations/{id}/ledger-roles` body `{roles:{output_cgst: ledger_id, ...}}` (replaces the whole map; roles listed in the schema) -> `{"ok":true}` | `422 errors G-08` (wrong group, other client's / inactive / unknown ledger, unknown role name)
- `POST /gst/validate-gstin` body `{gstin, on_date?}` -> `{valid, errors:[{rule_id, message}], state_code, state_name, pan, expected_check_char|null}` (no write; used by the screens as the user types)
- `GET /clients/{c}/gst/items?q=&kind=` -> `[GstItem]`; `GstItem = {id, name, item_kind: "goods"|"service", hsn_sac, uqc, sales_ledger_id|null, purchase_ledger_id|null, default_itc_category_key|null, default_rcm_category_key|null, is_active}`
- `POST /clients/{c}/gst/items` -> `201 {id}` | `422 G-07` | `422 invalid_name|invalid_ledger|invalid_category` | `409 item_exists`; `PUT /clients/{c}/gst/items/{id}`; deactivate via `is_active:false` (no delete)
- `GET /gst/rates/lookup?hsn_sac=&supply_kind=goods|services&on=` -> `{rule_id, rule_key, treatment: "taxable"|"exempt"|"nil_rated"|"non_gst", rate, cess_rate, cess_specific_amount, cess_uqc, is_default, is_example, verification_status, source_reference}` | `422 no_rate_rule` (G-10)
- Read-only rule tables, all accept `?on=` (default today) and return `{on, status:{overall, counts}, rows}` (`overall` = the weakest `verification_status` among the rows, no rows = pending; every row carries `verification_status` and `source_reference`): `GET /gst/state-codes`, `/gst/uqc`, `/gst/rate-slabs`, `/gst/rcm-categories`, `/gst/blocked-credit-categories`, `/gst/itc-conditions`, `/gst/composition-rules`, `/gst/thresholds`
- Party: `PUT /clients/{c}/parties/{ledger_id}` gains `gst_registration_type: "regular"|"composition"|"unregistered"|"sez"|"overseas"|"uin_holder"|"government"|null`; `Party` returns it. GSTIN errors are `G-01..G-04` in the GST registration / counterparty checks; on a party (`set_party`) the Phase 2 rules P-01..P-04 still apply until the switch noted in decisions_parts/A.md, so a party state code that differs from its GSTIN is reported as `P-04` (the test pack case W03 accepts P-04).

## Invoice-mode vouchers (package B)
`POST/PUT /clients/{c}/vouchers` (draft create / update, Phase 1 contract) accept an optional `gst` object. When `gst` is present, `lines` must be omitted (rule G-14: caller lines and tax amounts are rejected) and the service builds the ledger lines. Without `gst` nothing changes.
```
gst = {
  gst_registration_id,
  document_kind: "tax_invoice"|"bill_of_supply"|"self_invoice",
  supply_category: "b2b"|"b2c"|"sez_with_payment"|"sez_without_payment"|"export_with_payment"|"export_without_payment"|"deemed_export"|"unregistered_supplier"|"composition_supplier"|"import_of_service",
  place_of_supply,                    // state code; "96" for exports / imports of services
  invoice_date,                       // Sales: must equal voucher_date. Purchase: supplier's invoice date
  counterparty_gstin|null,            // default: the party's GSTIN; shown back
  original_invoice_no?, original_invoice_date?, note_reason?,   // Credit / Debit Note (G-24)
  items:[{
    item_id|null, description, hsn_sac, uqc|null,
    quantity, unit_rate, discount,    // discount is an amount
    ledger_id,                        // Sales / Purchase / expense / asset ledger of this item
    rcm_category_key|null,
    itc_category_key|null, itc_exception_claimed: false, itc_exception_note|null   // purchase only
  }],
  allocations?: [{kind, amount, bill_ref, due_date}]   // optional bill-wise allocation of the party line (Phase 2 shape);
                                                       // default for Sales / Purchase of a bill-wise party: new_ref, full invoice value, reference_no
}
```
`party_ledger_id`, `reference_no`, `voucher_date`, `narration`, `allocations` of the party line (optional; default `new_ref` = reference no, full invoice value) behave as before.
Response `Voucher` gains `gst`: header fields above + `invoice_value`, `invoice_round_off`, `has_rcm`, `engine_version`, `warnings:[{rule_id, message, item_line_no}]` (e.g. G-10 default rate used), and `items[]` with the engine's results: `{item_line_no, ..., gross_amount, taxable_value, treatment, gst_rate, cess_rate, cgst, sgst, igst, cess, rate_rule_id, rate_is_default, rcm, tax_in_cost}`; `lines[]` carry `gst_role` (`party|taxable|tax_cgst|...|round_off`) and `item_line_no`.
- Rule errors of an item line carry the ITEM number in `line_no` (the voucher lines are generated); `details.item_line_no` is not used. A tax amount, rate or ledger line typed in the request is refused as G-14 (item keys cgst, sgst, igst, cess, gst_rate, tax, tax_amount, taxable_value, ...).
- `POST /clients/{c}/vouchers/gst-preview` same body as create -> `{lines:[{ledger_id, ledger_name, debit, credit, gst_role}], gst:{...as above}, errors:[...]}` (no write; the screen shows tax lines read-only; errors as a list, 200 even when rules fail)
- Approve / post / reverse use the Phase 1 endpoints; G-26 and G-23 fire there (`422 errors`). Reversal vouchers mirror the lines; item rows are copied with the reversal link and `itc_entries` are marked reversed (C).
- Excel import (Phase 1.8 format) accepts extra optional columns for invoice mode: `gst_registration`, `supply_category`, `place_of_supply`, `item_description`, `hsn_sac`, `uqc`, `quantity`, `unit_rate`, `discount`, `item_ledger`, `itc_category`, `rcm_category`; rows with the same `ref_id` form one invoice (item rows have empty ledger_name / debit / credit). Also accepted, after the 13 standard columns and in any order: `document_kind` (required, never defaulted), `counterparty_gstin`, `original_invoice_no`, `original_invoice_date`, `note_reason`; `gst_registration` is the registration's GSTIN; the invoice date is the voucher date. Tax columns (cgst, sgst, igst, cess, gst_rate, tax_amount, taxable_value) are refused (G-14).

## ITC (package C)
`ItcEntry = {id, voucher_id, voucher_number, item_line_no, doc_type, source: "regular"|"rcm", supplier_ledger_id, supplier_name, supplier_gstin, supplier_invoice_no, supplier_invoice_date, igst, cgst, sgst, cess, status: "eligible"|"blocked"|"pending"|"reversed", pending_reason|null, blocked_category_key|null, tax_document_held, goods_services_received, received_date|null, supplier_tax_paid: "unknown"|"in_2b"|"not_in_2b"|"manual_confirmed", evidence_note|null, claim_deadline|null, claimed_in_period|null, days_since_invoice, unpaid_share: {fraction, igst, cgst, sgst, cess}|null}`
- `GET /clients/{c}/gst/itc?registration_id=&status=&period=&supplier_ledger_id=` -> `{entries:[ItcEntry], totals:{eligible:{igst,cgst,sgst,cess}, blocked:{...}, pending:{...}, reversed:{...}}}`
- `PUT /clients/{c}/gst/itc/{id}/evidence` body `{tax_document_held, goods_services_received, received_date?, supplier_tax_paid?, evidence_note?}` -> `ItcEntry` (re-classifies, appends an event; G-31)
- `POST /clients/{c}/gst/itc/{id}/confirm` body `{reason}` (manual confirmation for pending_2b, G-32) -> `ItcEntry`
- `GET /clients/{c}/gst/itc/{id}/events` -> `[{from_status, to_status, reason, actor, created_at}]`
- `POST /clients/{c}/gst/itc/{id}/tag-blocked` body `{category_key, note}` (identified late; creates a reversal proposal, G-30/G-36) -> `ItcEntry`
- `GET /clients/{c}/gst/itc/exposure-180?registration_id=&as_on=` -> `{as_on, rule_status, items:[{itc_entry_id, voucher_number, supplier_name, supplier_invoice_no, invoice_date, days, due_on_day, outstanding, unpaid_share, igst, cgst, sgst, cess, already_reversed: bool}], total:{igst,cgst,sgst,cess}}` (items with 180 days passed unpaid, plus a second list `approaching` for those within 30 days: `approaching:[...]`)
- `POST /clients/{c}/gst/itc/reversals` body `{registration_id, as_on, itc_entry_ids:[...]?}` (omitted = all due) -> `201 {created:[{reversal_id, itc_entry_id, voucher_id, igst, cgst, sgst, cess}]}` (DRAFT Journals Dr ITC Reversal / Cr Input tax; `409 reversal_exists`, `409 nothing_to_reverse`; rule errors `422 errors` when a ledger role is missing: `ledger_role_missing`)
- `GET /clients/{c}/gst/itc/reversals?status=` -> `[{id, itc_entry_id, reason, as_on_date, amounts, reclaimed amounts, reversal_voucher_id, reclaim_voucher_id, status}]`
- `POST /clients/{c}/gst/itc/reversals/{id}/reclaim` body `{as_on}` -> `201 {reclaim_voucher_id, igst, cgst, sgst, cess}` (draft Journal for the share paid since; G-35)
- `GET /clients/{c}/gst/itc/register-tie?registration_id=&as_on=` -> `{input_ledgers:{cgst,sgst,igst,cess: Balance}, itc_register:{...}, difference:{...}, ties: bool, notes:[...]}` (Input tax ledgers vs entries eligible + pending + reversed-adjusted)

## GSTR-2B / IMS import and reconciliation (package D)
- `POST /clients/{c}/gst/2b/import` multipart(file, registration_id, kind: "gstr2b"|"ims", period=`YYYY-MM`) -> `201 {import_id, documents, period, generated_on, totals:{taxable_value,igst,cgst,sgst,cess}}` | `422 import_invalid` (G-40) | `409 import_duplicate` (G-41)
- `GET /clients/{c}/gst/2b/imports?registration_id=` -> `[{id, kind, period, file_name, generated_on, document_count, created_at}]`; `GET /gst/2b/imports/{id}/documents` -> `[{id, section, supplier_gstin, supplier_name, doc_type, doc_no, doc_date, taxable_value, igst, cgst, sgst, cess, itc_available, itc_reason, ims_status, supplier_return_period}]`
- `GET /clients/{c}/gst/2b/reconciliation?registration_id=&period=` -> `{period, tolerance, summary:{matched, value_mismatch, gstin_mismatch, period_mismatch, only_in_books, only_in_2b}, rows:[{class, books:{voucher_id, voucher_number, supplier_gstin, supplier_invoice_no, invoice_date, taxable_value, igst, cgst, sgst, cess, itc_status}|null, doc_2b:{document_id, supplier_gstin, doc_no, doc_date, taxable_value, igst, cgst, sgst, cess, itc_available, ims_status}|null, differences:[{field, books, doc_2b, difference}], note, link_id|null}], totals:{books:{...}, doc_2b:{...}, difference:{...}}}` (computed on demand; ambiguous cases appear with class `ambiguous` and the candidate list in `note`; G-42/G-44)
- `POST /clients/{c}/gst/2b/links` body `{document_id, voucher_id, link_kind: "manual"|"accepted_difference", note}` -> `201 {link_id}` | `409 link_exists|link_invalid` (G-43)
- `DELETE /clients/{c}/gst/2b/links/{id}` -> 204
- `POST /clients/{c}/gst/2b/apply?registration_id=&period=` -> `{updated:[{itc_entry_id, from_status, to_status}], applied, effects:[{voucher_id, supplier_tax_paid, pending_reason, note}]}` (`applied=false`, `updated=[]` while C's `gst_itc.apply_2b_result(conn, client_id, registration_id, period, effects, actor)` does not exist; applies the reconciliation to the ITC register: matched -> `supplier_tax_paid = in_2b`; only in books -> `pending not_in_2b`; IMS rejected/pending -> pending; never marks anything eligible without the evidence of G-31)

## GSTR-1, GSTR-3B, tie-out, composition (package E)
Common: `period` = `YYYY-MM` for monthly; for QRMP and composition `period_kind=quarter` with `period_start=YYYY-MM-01` (the quarter's first month). All amounts 2-decimal strings. Every working returns `{registration_id, gstin, period_kind, period_start, period_end, generated_at, rule_status, warnings:[...], tables:{...}, source_voucher_count, unposted_drafts_in_period:[{voucher_id, ...}]}` and is computed from POSTED vouchers only (G-56).
- `GET /clients/{c}/gst/gstr1?registration_id=&period_start=&period_kind=` -> `tables`: `b2b:[{party_gstin, party_name, invoices:[{invoice_no, invoice_date, invoice_value, place_of_supply, reverse_charge, supply_type, items:[{rate, taxable_value, igst, cgst, sgst, cess}]}]}]`, `b2cl:[{place_of_supply, invoices:[...]}]`, `b2cs:[{place_of_supply, rate, taxable_value, igst, cgst, sgst, cess}]`, `cdnr:[{party_gstin, notes:[{note_no, note_date, note_type: "C"|"D", original_invoice_no, original_invoice_date, reason, items:[...]}]}]`, `cdnur:[...]`, `exports:[{export_type: "with_payment"|"without_payment", invoices:[...]}]`, `sez:[...]`, `nil_exempt_non_gst:{inter_registered, intra_registered, inter_unregistered, intra_unregistered}` each `{nil_rated, exempt, non_gst}`, `hsn_summary:[{hsn_sac, description, uqc, quantity, total_value, taxable_value, igst, cgst, sgst, cess, rate}]`, `documents_issued:[{nature, from_no, to_no, total, cancelled, net_issued}]`, `totals:{taxable_value, igst, cgst, sgst, cess}` (table numbering shown as `portal_table` per entry, to be confirmed against the portal: PHASE3_LEGAL_VALUES.md section 5)
- `GET /clients/{c}/gst/gstr3b?registration_id=&period_start=&period_kind=` -> `tables`: `t3_1:{a_outward_taxable, b_zero_rated, c_nil_exempt, d_inward_rcm, e_non_gst}` each `{taxable_value, igst, cgst, sgst, cess}`, `t3_2:{unregistered:[{place_of_supply, taxable_value, igst}], composition:[...], uin:[...]}`, `t4:{a:{import_goods, import_services, inward_rcm, isd, all_other_itc}, b:{rule_38_42_43_and_17_5, others}, c_net, d_ineligible}` each `{igst, cgst, sgst, cess}` (4(A)(5) all other ITC = eligible entries claimed in the period; 4(B)(2) includes 180-day reversals; 4(D) ineligible = blocked + pending not claimed, shown as information), `t5:{inter_composition_exempt, intra_composition_exempt, inter_nil, intra_nil, non_gst}`, `t6_1:{tax_payable:{...}, itc_utilised:{...}, cash:{...}}` (utilisation order per Section 49 is a rule to be confirmed by the CA: the working shows liability and ITC available per head and the cash balance with the utilisation order named in `notes`; no automatic offset beyond the legal order if confirmed, else `utilisation: "not_computed"`)
- `POST /clients/{c}/gst/workings` body `{registration_id, return_type, period_start, period_kind}` -> `201 {working_id, version}` (saves the working as a draft version); `POST /gst/workings/{id}/finalise` -> `{"ok":true}` (then immutable, `409 working_final` on any change); `GET /clients/{c}/gst/workings?registration_id=&return_type=` -> `[{id, return_type, period_start, version, status, data_hash, created_by, created_at}]`; `GET /gst/workings/{id}`
- `PUT /clients/{c}/gst/filed-returns` body `{registration_id, return_type, period_start, arn?, filed_on?, data}` (`data` = the same `tables` shape with only the figures the accountant typed or imported from the portal's summary; replaces) -> `{"ok":true}`; `GET` same path with query -> record
- `GET /clients/{c}/gst/tie-out?registration_id=&period_start=&period_kind=` -> `{rows:[{head: "taxable_value"|"igst"|"cgst"|"sgst"|"cess", books_output, gstr1_working, gstr3b_working, filed_gstr1|null, filed_gstr3b|null, d_books_gstr1, d_gstr1_gstr3b, d_books_filed}], itc:{books_input, itc_register_eligible, gstr3b_4a, ...}, causes:[{kind: "draft_voucher"|"manual_journal_on_tax_ledger"|"other_period_document"|"pending_itc"|"rounding", reference, amount}], ties: bool}` (differences are shown, never forced; G-53)
- `GET /clients/{c}/gst/composition?registration_id=&period_start=` (quarter) -> `{category, rate, rate_status, quarter_turnover, turnover_basis, tax:{cgst, sgst, total}, ytd_turnover, limit, limit_crossed: bool, warnings:[...], invoices_with_tax:[...] }` (G-54; `422 not_gst_client`/`errors` when the registration is not composition)
- Exports (all return a file; response header `X-Rule-Status`): `GET /gst/workings/{id}/export.xlsx`, `GET /clients/{c}/gst/gstr1/export.xlsx|json?...`, `GET /clients/{c}/gst/gstr3b/export.xlsx|json?...`, `GET /clients/{c}/gst/tie-out/export.xlsx?...`. JSON files carry the same figures as the working, in the portal's offline-tool structure **as understood**; until an official sample is checked the JSON response body has the header `X-Format-Status: unverified-against-portal-schema`. Excel: one sheet per table, numbers as numbers (2 decimals), rule statuses on the first sheet.

### Package E as built (deviations from the section above)
- Working responses carry the common envelope plus `tables`. GSTR-1 `tables` also has `unclassified`, `portal_tables` (+ `portal_tables_status: "pending"`); `totals` includes nil/exempt/non-GST; table 8 values are `{nil_rated, exempt, non_gst}`; cdnur notes carry `unregistered_type`. GSTR-3B: `t4.a` and `t4.b` also have `total`, `t3_2` also lists `composition` and `uin`, `t5` values are `{taxable_value}`, `t6_1` = `{tax_payable, rcm_payable_in_cash, itc_available, utilisation: "not_computed", itc_utilised: null, cash: null, notes}`; `outward_total` is the 3.1 (a)+(b)+(c)+(e) sum used by the tie-out.
- `GET .../gst/tie-out` returns the envelope with `rows, itc, causes, ties` also at top level (and under `tables`); rows add `d_filed_gstr1_gstr3b`; `itc` is per head `{books_input, itc_register_eligible, gstr3b_4a (= 4(A) less 4(B)), itc_register_pending, d_register_gstr3b, d_books_register_pending}`; causes carry an optional `head`.
- `GET .../gst/composition` returns the envelope with the working fields also at top level (and under `tables.cmp08`).
- `GET .../gst/filed-returns` needs `registration_id, return_type, period_start`; 404 when none entered. Extra 422 codes: `period_invalid`, `not_gst_client`, `filed_invalid`, `working_unsupported`.
- `GET /gst/workings/{id}` returns the stored envelope under `data`.

## Frontend screens (package F)
Registrations (+ GSTIN live check, ledger-role map); Item master; Rules viewer (status badge per table; amber when `pending`); Invoice-mode voucher entry (header with registration and place of supply, item grid, read-only tax preview from `gst-preview` on every change, warnings, ITC tag and RCM tag per item on purchases, the allocation editor of Phase 2 for the party line); ITC register (filters, evidence panel, manual confirm, tag blocked, events); 180-day exposure with "Create reversal drafts" and the reclaim action; 2B import + reconciliation (tabs for the six classes, manual link, accept difference with note, apply to ITC); GSTR-1 working, GSTR-3B working, Tie-out, Composition working; Workings list with finalise and downloads. Dense and table-first; no calculation of tax in the browser; amounts as strings with BigInt-paise display helpers.
